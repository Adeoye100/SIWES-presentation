08 — Challenges

Three problems.
Three lessons.

Real engineering is not the absence of problems. It is knowing how to move through them.

API endpoints returned inconsistent data shapes. I learned to inspect the request, the payload, and the server response systematically — not randomly. The fix was structured: read the contract, then read the code.

UI components drifted across pages as the codebase grew. I addressed it with shared component files and defined spacing and color tokens. Reusability is not a shortcut — it is a discipline.

Features arrived half-specified. Coding first produced the wrong result every time. I built the habit of writing a one-page summary: who is the user, what do they expect, what does success look like — before any code was written.

09 | CONCLUSION & REFLECTION

Building Better Software Systems

The SIWES placement turned classroom theory into practical engineering experience. I now focus on building reliable software with clean structure and user-centered design.

Reflection Q&A
Moving from just building isolated frontend UI components to thinking about full-stack data flow, API performance, and seamless user experiences.
Real-world work showed that code must handle edge cases cleanly and provide clear feedback. Error handling, structured process, and reliability matter just as much as writing neat functions.
It focused my career goals on web systems engineering and building reliable, scalable platforms for actual users.
